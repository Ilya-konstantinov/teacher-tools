# Распределение на коллоквиум

Python 3.10+, без дополнительных библиотек. Запуск из этой папки:

В `examples/` приведены демонстрационные таблицы с условными именами. **Время заявок вымышленное**, только для демонстрации сортировки и дедлайна. Перед реальным распределением укажите настоящие данные.

```sh
python3 schedule_students.py --examiners examples/examiners.tsv --students examples/students.tsv --minutes-per-student 30 --output schedule.tsv
```

С дедлайном (в таблице студентов обязательно время каждой заявки):

```sh
python3 schedule_students.py --examiners examples/examiners.tsv --students examples/students.tsv --deadline '01.11.2026 12:04:00' --output schedule.tsv
```

## Настройки

Значения по умолчанию находятся в [config.json](config.json). Секция `schedule` задаёт `minutes_per_student`, `prep_minutes` и выходной файл расписания; секция `workload` — выходной файл отчёта, порог предупреждения `warning_ratio` и цвета нагрузки. Порог должен быть больше 0 и не превышать 1, цвета — в формате `#RRGGBB`.

Можно передать частичные настройки через `--config`. Например, `local/custom.json`:

```json
{
  "schedule": {"minutes_per_student": 20, "prep_minutes": 40},
  "workload": {"warning_ratio": 0.85}
}
```

```sh
python3 schedule_students.py --config local/custom.json \
  --examiners examples/examiners.tsv --students examples/students.tsv
python3 schedule_tools.py workload --config local/custom.json \
  --schedule schedule.tsv --examiners examples/examiners.tsv
```

Приоритет: **явный аргумент CLI → пользовательский JSON → config.json проекта**. Оба инструмента берут длительности из секции `schedule`; передавайте им одинаковый `--config`. Если длительность переопределена только в команде распределения, соответствующее значение нужно передать и отчёту через `--exam-minutes`/`--prep-minutes`. При использовании `--capacity` длительность проверки для отчёта равна `60 // capacity`.

Неизвестные поля, неверные типы и недопустимые значения отклоняются до записи результата. Относительные пути считаются от текущей рабочей папки. Конфиг проекта находится рядом со скриптами независимо от папки запуска. Низкоуровневая функция `allocate()` не читает JSON; её прежние значения по умолчанию сохранены.

## Входные данные

Сохраните таблицу в UTF-8 TSV (значения разделены табуляцией) или CSV. Для CSV поддерживаются запятая и точка с запятой; при разделителе-запятой списки часов должны быть в кавычках. Первая строка — заголовок. XLSX напрямую не читается.

Принимающие: две колонки — ФИО, часы через запятую. Название заголовка произвольное, в том числе `ФИОВремя прием`, как в исходном примере. Час 14 означает доступность 14:00–15:00. Соседние часы объединяются по смыслу в непрерывную доступность.

По умолчанию студент приходит, готовится **40 минут**, затем сдаёт **30 минут**. `--prep-minutes` задаёт подготовку (можно 0), `--minutes-per-student` задаёт длительность проверки от 1 до 60 минут и шаг прихода батчей. Для 30 минут приходы — ЧЧ:00 и ЧЧ:30; для 20 — ЧЧ:00, ЧЧ:20, ЧЧ:40. Начало прихода — не раньше самого раннего часа из таблицы принимающих.

Вместимость батча равна числу принимающих, каждый из которых доступен на **всей проверке** `[приход + подготовка, приход + подготовка + проверка)`. Например, пришедшие в 14:30 проверяются в 15:10–15:40: доступность в 14 часов не даёт им мест. При проверке 14:40–15:10 учитываются только принимающие, доступные и в 14, и в 15 часов. Принимающий не меняется посередине проверки.

Батчей в одном часе прихода — `60 // minutes_per_student` (округление вниз); оставшиеся минуты свободны. Вместо длительности можно указать `--capacity` (1–60), тогда столько батчей создаётся в каждом часе с длительностью проверки `60 // capacity`. Параметры взаимоисключающие. Индивидуальные длительности не моделируются. Для вызова Python-функции `allocate` подготовку нужно передать явно: `prep_minutes=40` (значение API по умолчанию 0 для совместимости); CLI по умолчанию использует 40.

Студенты: `ФИО`, `Группа`, `Приоритет 1`, `Приоритет 2`, `Приоритет 3`, `В какое время вы точно не сможете`. Порядок колонок произвольный. Приоритеты относятся к часу **прихода**. Запреты действуют на весь период присутствия — от прихода до конца подготовки и проверки: пересечение любого запрещённого часа исключает батч. Приоритеты и запреты можно оставить пустыми. Часы: `9` или `9:00`; диапазоны не поддерживаются. Повторяющийся час в приоритетах получает наивысший из указанных приоритетов. Группа сохраняется как текст и не ограничивает принимающих.

Необязательная колонка `Время заявки` или `Отметка времени`: `01.11.2026 12:00:00`, `01.11.2026 12:00` или ISO `2026-11-01 12:00:00`. Все даты должны быть в одном часовом поясе. Если колонка есть, она должна быть заполнена для всех. Если её нет, временем подачи считается порядок строк; `--deadline` в этом случае использовать нельзя. При одинаковом времени преимущество имеет верхняя строка.

Повторы ФИО принимающего или пары ФИО/группа студента считаются ошибкой: повторные заявки нужно сначала согласовать вручную.

## Правила распределения

Строго в следующем порядке:

1. Максимизировать общее число распределённых студентов, соблюдая доступность и вместимость.
2. Среди таких решений распределить как можно больше своевременных заявок.
3. Минимизировать сумму штрафов: первый приоритет — 0, второй — 1, третий — 2, другое допустимое время — 3. Для опоздавших любой разрешённый час имеет штраф 3, пожелания игнорируются.
4. При равных предыдущих показателях выбрать лучшее время для самой ранней заявки, затем для следующей и т. д. Нераспределение хуже любого допустимого часа.

Дедлайн включительный: заявка ровно в дедлайн своевременная. Даже у опоздавших запрещённые часы исключаются. Приоритеты являются пожеланиями: возможно назначение в любой другой незапрещённый час. Это глобальная оптимизация, а не последовательная выдача мест: ранняя заявка не может ухудшить число распределённых или суммарное качество. Конкретные принимающие студентам не назначаются: учитываются места в каждом батче с гарантией доступности одного принимающего на всю проверку.

Результат — TSV с колонками `Время прихода` (ЧЧ:ММ), `ФИО`, `Группа`, `Приоритет`, `Причина`, отсортированный по времени прихода и ФИО. Время подачи заявки используется внутри алгоритма для приоритетов, но в итоговое расписание не выводится. Пустой приоритет означает время вне пожеланий либо опоздавшую заявку. Если места нет, время прихода пустое, указана причина. Опоздавшие назначения также помечаются в колонке «Причина».

## Алгоритм

Используется максимальный поток минимальной стоимости с точным учётом приоритетов. Модель графа, доказательства порядка целей и асимптотика описаны в [ALGORITHM.md](ALGORITHM.md).

## Отчёт нагрузки

`schedule_tools.py workload` строит таблицу и HTML-отчёт нагрузки по расписанию:

```sh
python3 schedule_tools.py workload --schedule schedule.tsv --examiners examples/examiners.tsv --prep-minutes 40 --exam-minutes 30 --output workload.tsv
```

## Структура и проверки

```text
colloq_time/
├── examples/       # Таблицы с условными именами
├── src/            # Распределение, ввод-вывод, отчёт нагрузки
├── tests/
├── schedule_students.py  # Основная задача
├── schedule_tools.py     # Нагрузка и тесты
├── config.json           # Настройки расписания и отчёта
├── README.md
└── ALGORITHM.md
```

Основная задача: `schedule_students.py`. Вспомогательные команды: `schedule_tools.py workload` и `schedule_tools.py test`. Справка: `python3 schedule_students.py --help` и `python3 schedule_tools.py --help`.

```sh
python3 schedule_tools.py test
```

Тесты проверяют вместимость, запреты на всём присутствии, подготовку, пересечение часовых границ проверки, время подачи, дедлайн, перераспределение и сравнивают небольшие случайные задачи с полным перебором. Также проверяются переопределение настроек CLI/JSON и согласованность длительностей расписания и отчёта.

Реальные заявки и локальные результаты можно хранить в `.test/` или `local/`: они исключены из Git.

Реализация состоит из пяти модулей: `src/data.py` (модели и таблицы), `src/allocation.py` (распределение), `src/workload.py` (нагрузка), `src/cli.py` (аргументы основной задачи), `src/config.py` (загрузка и проверка настроек).
